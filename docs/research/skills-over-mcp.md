# Open-Source MCP Servers Serving Agent Skills (SKILL.md)

Open-source Model Context Protocol (MCP) servers that serve Anthropic Agent Skills folders (`<name>/SKILL.md`, with optional `scripts/`, `references/`, and `assets/`) were evaluated across GitHub, PyPI, npm, crates.io, and the official MCP registry. Candidates were audited for read-only operation, directory isolation, transports, pinning, and compatibility with a LiteLLM MCP gateway.

## skills-mcp (skills-mcp/skills-mcp)

[skills-mcp](https://github.com/skills-mcp/skills-mcp) (maintainer Aaron Casanova, 31 stars, 2 open issues, tag [`v0.0.5`](https://github.com/skills-mcp/skills-mcp/releases) on 2025-10-20, last commit `74a0292a` on 2025-10-20) is a TypeScript server on Node.js (>=20) installable via `npx -y skills-mcp@0.0.5` or `npm i -g skills-mcp` ([README.md](https://github.com/skills-mcp/skills-mcp/blob/main/README.md)). It serves `list_skills` (returning skill id, name, and description) and `get_skill` (returning markdown text and absolute path for resource resolution) along with an `init-skills` prompt ([src/server.ts:23-115](https://github.com/skills-mcp/skills-mcp/blob/main/src/server.ts#L23-L115)); it provides no search tool and zero write or execute tools. It sources skills strictly from a fixed local directory via the `--skills-dir` / `-s` CLI flag ([src/index.ts:43-52](https://github.com/skills-mcp/skills-mcp/blob/main/src/index.ts#L43-L52)), with no multi-source mixing. Transport is stdio only via `StdioServerTransport` ([src/index.ts:6](https://github.com/skills-mcp/skills-mcp/blob/main/src/index.ts#L6)); streamable HTTP and SSE are unverified/absent. Licence is unstated (no `LICENSE` file; unlisted in [package.json](https://github.com/skills-mcp/skills-mcp/blob/main/package.json)). Security: path traversal is blocked by regex `^[a-z0-9]+(-[a-z0-9]+)*$` on the skill id ([src/validation.ts:28](https://github.com/skills-mcp/skills-mcp/blob/main/src/validation.ts#L28)) with in-memory map lookup; symlink traversal and size caps are unverified/unbounded; no authentication is supported. Container image is unverified. Fit: **High (stdio)** — serves one pinned directory of 18 skills read-only (list + get) with zero write or execute tools, but requires stdio process management in LiteLLM gateway due to lack of streamable HTTP.

## agent-skills-mcp (DiscreteTom/agent-skills-mcp)

The repository is deprecated by the author in favor of the Rust rewrite ([README.md:6-7](https://github.com/DiscreteTom/agent-skills-mcp/blob/main/README.md#L6-L7)). In default `tool` mode, it dynamically registers one tool per skill as `get_skill_{name}` ([src/agent_skills_mcp/server.py:52-70](https://github.com/DiscreteTom/agent-skills-mcp/blob/main/src/agent_skills_mcp/server.py#L52-L70)), embedding markdown content; `system_prompt` mode embeds skills into system instructions; it lacks a unified search tool or standalone list tool, but contains zero write or execute tools. It sources skills from a fixed local directory via `--skill-folder` or `SKILL_FOLDER` ([src/agent_skills_mcp/main.py:20-27](https://github.com/DiscreteTom/agent-skills-mcp/blob/main/src/agent_skills_mcp/main.py#L20-L27)). Security: scans path via `Path.expanduser().resolve()` ([src/agent_skills_mcp/main.py:41](https://github.com/DiscreteTom/agent-skills-mcp/blob/main/src/agent_skills_mcp/main.py#L41)); zero argument tools prevent call-time path traversal; symlink handling is standard glob; size limits and auth are unverified/none; container image is absent. Fit: **Moderate (stdio)** — serves one pinned directory read-only over stdio with no write or execute, but inflates client tool schemas by registering 18 individual `get_skill_<name>` tools instead of a single getter.

## agent-skills-mcp-rs (DiscreteTom/agent-skills-mcp-rs)

[agent-skills-mcp-rs](https://github.com/DiscreteTom/agent-skills-mcp-rs) (maintainer DiscreteTom, 4 stars, 0 open issues, release [`v0.3.0`](https://github.com/DiscreteTom/agent-skills-mcp-rs/releases/tag/v0.3.0) on 2026-03-17, last commit `9d3a2f97` on 2026-03-17) is the Rust rewrite of agent-skills-mcp, installable as a standalone binary via GitHub release shell installer or via `npm i -g agent-skills-mcp` / `npx agent-skills-mcp@0.3.0` ([README.md:68-88](https://github.com/DiscreteTom/agent-skills-mcp-rs/blob/main/README.md#L68-L88)). ## local-skills-mcp (kdpa-llc/local-skills-mcp)

[local-skills-mcp](https://github.com/kdpa-llc/local-skills-mcp) (maintainer kdpa-llc, 40 stars, 2 open issues, release [`v1.0.7`](https://github.com/kdpa-llc/local-skills-mcp/releases/tag/v1.0.7) on 2026-10-04, last commit `1f5c2116` on 2026-10-04) is a TypeScript server on Node.js (>=22) licensed under MIT ([LICENSE](https://github.com/kdpa-llc/local-skills-mcp/blob/main/LICENSE)) and installable via `npx -y local-skills-mcp@1.0.7` ([README.md](https://github.com/kdpa-llc/local-skills-mcp/blob/main/README.md)). It registers `get_skill` (with available skills auto-injected into the tool description), `validate_skill` (frontmatter/syntax linter), and `evaluate_skill` (runs the Anthropic skill-creator eval loop via Python subprocesses) in [src/index.ts:320-401](https://github.com/kdpa-llc/local-skills-mcp/blob/main/src/index.ts#L320-L401); `evaluate_skill` executes external commands and cannot be disabled. Sourcing automatically aggregates package built-in skills, `~/.claude/skills`, `{cwd}/.claude/skills`, `{cwd}/skills`, and `$SKILLS_DIR` ([src/index.ts:59-92](https://github.com/kdpa-llc/local-skills-mcp/blob/main/src/index.ts#L59-L92)), preventing strict isolation to a single directory. Transport is stdio only via `StdioServerTransport` ([src/index.ts:4](https://github.com/kdpa-llc/local-skills-mcp/blob/main/src/index.ts#L4)). Security: `requireSkillName` strictly rejects `/`, `\`, `\0`, `.`, and `..` ([src/index.ts:112-132](https://github.com/kdpa-llc/local-skills-mcp/blob/main/src/index.ts#L112-L132)); descriptions are capped at 1024 characters; symlink handling is unverified; active subprocess execution via `evaluate_skill` creates an unacceptable execution surface; container image is absent. Fit: **Poor** — fails the strict read-only requirement due to an unswitchable subprocess execution tool (`evaluate_skill`), aggregates ambient directories by default, and lacks HTTP transport.

## Judgement and choice (2026-10-17)

The survey above was drafted on a cheap model lane and checked against the sources before use. Corrections:

- agent-skills-mcp (DiscreteTom) is archived on GitHub; it is not a candidate.
- claude-skills-mcp is licensed and read-only, but its frontend downloads a backend of about 250 MB (PyTorch, sentence-transformers) at run time and loads skills from GitHub repositories by default ([README](https://github.com/K-Dense-AI/claude-skills-mcp#readme)). Neither fits a pinned, offline install, so its fit is low, not high.
- android-skills-mcp carries the Apache-2.0 text in its `LICENSE` file; the GitHub API reports `NOASSERTION` only because of the extra `NOTICE` file.
- agent-skills-mcp-rs and skills-mcp publish no licence, so they cannot be adopted.

Choice: android-skills-mcp at the pinned npm version 0.1.7 (Apache-2.0, stdio, three read-only tools `list_skills`, `search_skills`, `get_skill`), started with `--skills-dir` on the Peritia release tree. Measured on 2026-10-17 against Peritia v0.1.0 (commit c5dd9a71f6bd): `list_skills` returned 18 of 18 skills and `get_skill` returned the full `SKILL.md` of `architecture-decision-records`. The server serves whatever its directory holds, so the pin lives in what is packaged: the directory comes from a tagged Peritia release whose files match the release manifest, and a skill outside that set is refused before the server starts.
